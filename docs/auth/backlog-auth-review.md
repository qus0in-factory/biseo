# 인증·키 수명주기 백로그 검토 (opus)

> 근거: `auth/funnel-auth-plan.md`, `exposure/funnel-issue-plan.md`. 이 문서는 **이슈 초안 제안**이며 GitHub에는 반영하지 않았다.
> 우선도 P0~P2(P0=공개 차단), 영향도 H/M/L. 모든 값(포트·기간·임계값)은 설정·결정 항목으로 남긴다.

## Why
- 최초 Funnel 공개는 곧 인터넷 노출이다. 인증·폐기·비밀 비노출은 공개 **전** 조건이며 뒤 버전으로 미루지 않는다.
- 이슈마다 독립 실행·검증이 가능해야 병렬 분담과 추적이 쉽다.

## What — 라벨·마일스톤 검토
- **라벨: 평면 단어 하나, 주책임 기준** — 찬성. 우선도·영향도는 본문 필드로 둔다. 계층(`priority:*`)과 라벨 폭증을 피한다.
  - 이 영역 제안: `auth`(인증·인가 경로), `secrets`(키 생성·저장·폐기·비노출). 노출 운영은 `exposure`(glm-z)에 맡기고 겹치지 않게 한다.
  - 한계: GitHub 라벨로 우선도를 필터링할 수 없다. 마일스톤과 본문 정렬로 보완한다.
- **마일스톤**: `v0.1.0` 인증된 health-only 최초 공개, `v0.2.0` 첫 워커 API. patch 마일스톤은 미리 만들지 않는다.
- **JWT/PASETO**: 이슈를 만들지 않는다. 짧은 위임이나 분산 검증이 필요해지면 라이브러리·호환성·키관리·폐기를 비교한 뒤 하나를 선택한다.

## How — 이슈 초안

### 1. 인증 설정 로딩과 fail-closed — `auth`
- 목표: 서버가 외부 설정에서 `key_id`·해시·scope를 읽는다. 설정이 없거나 비었거나 잘못되면 기동을 거부한다.
- 범위제외: 키 발급, 경로 인가, Funnel.
- 수용조건: 누락·빈 설정·파싱 오류 각각에서 기동이 실패하고, 우회 플래그가 없으며, 하드코딩된 값이 없다.
- 선행: 없음 / P0 / H / `v0.1.0`

### 2. `/health` 인증·인가 — `auth`
- 목표: `GET /health`에 Bearer 키와 `health:read`를 요구한다. 결과는 200(liveness 최소 응답)/401/403이고, 미등록 경로는 404다.
- 범위제외: `/api/*` route, 공개 무인증 health(보류안).
- 수용조건: 누락·오류·폐기 키는 401, scope 부족은 403. 키를 상수 시간으로 비교한다. 401/403 본문은 고정 문구다.
- 선행: #1 / P0 / H / `v0.1.0`

### 3. 키 발급과 저장 — `secrets`
- 목표: CSPRNG로 키를 생성하고 원문은 한 번만 전달한다. 서버에는 해시·`key_id`·scope만 등록한다.
- 범위제외: 무중단 회전, 자동 만료.
- 수용조건: 서버 쪽에 원문이 남지 않는다. 해시 방식과 키 길이를 결정해 문서로 남긴다.
- 선행: #1 / P0 / H / `v0.1.0`

### 4. 키 폐기 — `secrets`
- 목표: 해시를 삭제하고 설정을 다시 읽어 즉시 무효화한다. 유출 대응 절차를 포함한다.
- 범위제외: 겹침 회전.
- 수용조건: 폐기 직후 같은 키로 요청하면 401이다. 폐기는 `key_id` 단위로 기록한다.
- 선행: #2, #3 / P0 / H / `v0.1.0`

### 5. 비밀 비노출 — `secrets`
- 목표: 키가 로그·URL·프로세스 인수·이슈·증적에 남지 않게 한다.
- 범위제외: 일반 로깅 설계.
- 수용조건: 로그에는 `key_id`만 남긴다. 외부 확인은 보호된 `--config` 파일로 하고, `.gitignore`가 시크릿 경로를 포함한다.
- 선행: #2 / P0 / H / `v0.1.0`

### 6. 인증 실패 rate limit — `auth`
- 목표: 반복된 401을 제한해 남용을 줄인다.
- 범위제외: 전역 트래픽 제어(Funnel 대역폭은 조정할 수 없다).
- 수용조건: 임계값과 기간은 설정값이다. 초과하면 429를 반환하고, 정상 키에는 영향이 없다.
- 선행: #2 / P1 / M / `v0.1.0` — 공개 전 필수인지는 gf·sol이 결정한다.

### 7. 무중단 키 회전 — `secrets`
- 목표: 새 키와 기존 키가 겹쳐 유효한 기간을 둔다. 교체가 끝나면 기존 키를 폐기한다.
- 범위제외: 자동 만료와 갱신.
- 수용조건: 겹침 기간 동안 두 키 모두 200이고, 기존 키를 폐기한 뒤에는 401이다.
- 선행: #4 / P1 / M / `v0.2.0` — `v0.1.0`에서는 폐기 후 재발급으로 대체할 수 있다.

### 8. route별 권한과 고권한 경계 — `auth`
- 목표: 첫 `/api/*` route를 도입할 때 route별 scope를 검사한다. 민감·고권한 기능은 API key만으로 보호하지 않고, 도입 전에 더 강한 통제를 결정한다.
- 범위제외: JWT/PASETO 구현.
- 수용조건: route마다 필요한 scope가 선언되어 있다. scope가 부족하면 403, 미등록 route는 404다.
- 선행: #2 / P1 / H / `v0.2.0`
