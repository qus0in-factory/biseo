# Funnel 계획 협업 기록

## Why

외부 HTTPS 443 헬스체크를 작은 첫 단계로 만들고, 이후 워커 호출 API에 필요한 인증·인가를 처음부터 계획한다. 이번 작업의 완료 대상은 설계 문서·수용 조건·GitHub 계획 이슈이며 서비스 공개는 구현 단계에 수행한다.

## What

2026-10-28 Herdr에서 기존 워커를 조회하고 화면·상태를 확인한 뒤 분담했다. 새 워커나 별도 작업 디렉터리를 만들지 않았으며, 담당 파일을 나눠 공유 작업 공간에서의 충돌을 피했다.

| 현재 별칭 | 역할 | 담당 산출물 |
| --- | --- | --- |
| `sol` | 공식 문서 확인, 통합 검토, 운영 기록·스킬화, 이슈 게시 | 이 문서, release/repository-history.md, 워크스페이스 docs·공통 스킬, GitHub 이슈 |
| `opus` | Funnel 경계와 인증 방식·시크릿 수명주기 설계 | [auth/funnel-auth-plan.md](../auth/funnel-auth-plan.md) |
| `ds-o` | Given/When/Then 수용 조건과 검증 계획 | [exposure/healthcheck-acceptance.md](../exposure/healthcheck-acceptance.md) |
| `glm-z` | 독립 노출·운영·설정 충돌·원복 검토 | [exposure/exposure-review.md](../exposure/exposure-review.md) |
| `gf` | 공통·프로젝트 문서의 누락·중복 검토 | 워크스페이스 `docs/harness/documentation-review.md` |

GF 탭과 연결된 단일 패널의 존재를 확인하고 세 라벨을 `gf`로 동기화한 뒤 문서 완결성 검토를 배정했다.

GLM의 탭 라벨을 현재 목록에서 확인하고 pane·워커 이름도 `glm-z`로 동기화한 뒤 독립 검토를 배정했다.

DS는 초기 배정 때 `ds`였고 사용자의 정정에 따라 `ds-o`로 탭·pane·워커 이름을 통일했다. ID는 문서에 고정하지 않으며 다음 통신 전에 다시 조회한다.

## How

1. **배정**: 읽을 지침·공식 문서·완료 조건·수정할 파일을 명시했다. AGENTS.md·CLAUDE.md·README.md 편집, 비밀 발급, 서비스 실행·노출, 커밋·푸시·이슈 게시는 워커에게 배정하지 않았다.
2. **초안 검토**: 워커 완료 상태뿐 아니라 실제 문서를 읽고 공식 자료와 비교했다. 초기 공개 무인증 health 제안은 사용자의 인증 요구에 맞춰 보호 health 제안으로 수정 요청했다.
3. **인증 개념 정리**: TLS와 인증·인가를 구분했다. JWT 서명과 PASETO public은 암호화가 아니며 PASETO local은 인증된 암호화라는 차이를반영하도록 요청했다. 특정 토큰 방식의 자동 도입 대신 필요 발생 시 재평가한다.
4. **운영 검토**: macOS 배포형에 관한 공식 문서의 표현 차이는 설치본 확인 전 미정으로 남긴다. 공유 설정 전체 reset을 일반 중지로 사용하지 않고 기존 상태와 대상 443 구성을 확인한다.
5. **수용 조건 통합**: 정상·미인증·잘못된 인증·폐기·권한부족·제한·장애·복구를 구분한다. 제안 성능값과 인증 방식별 후속 조건을 확정된 구현 결과로 기록하지 않는다.
6. **기록**: 범용 GitHub 운영은 전용 스킬로, Herdr 협업 계획 절차는 기존 스킬의 참조로, 과거 공통 결정은 워크스페이스 docs로 분리한다.

### 현재 검증 범위

- 확인: 공식 문서, 워커의 메시지 수신·문서 작성, 라벨 동기화, 문서 간 정합성과 형식.
- 미수행: 실제 Tailscale 설치·정책 변경·Funnel 활성화, API 서버 구현·실행, 외부 통신·인증·장애 테스트, 비밀 생성.
- 문서의 체크리스트는 앞으로 수행할 작업이며 통과한 테스트 목록이 아니다.

### 게시 결과

- [계획 이슈 #1](https://github.com/qus0in-factory/biseo/issues/1)을 생성하고 OPEN 상태·본문·라벨 없음으로 확인했다.
- 연결 GitHub 앱은 새 저장소에 대한 이슈 쓰기 권한이 없어 403을 반환했다. 사용자 요청 범위 안에서 인증된 gh CLI로 게시했다.
- 상세 문서는 로컬에 작성했으며 이번 문서 변경은 아직 커밋·푸시하지 않았다.
- 독립 검토가 완료되면 통합 반영 결과를 여기에 추가한다.

### 통합 반영

- Opus 개정안의 보호 health·fail-closed·CSPRNG·시크릿 비노출과 DS의 P1/P2 검증 조건을 대조했다. curl 인증은 보호된 설정 파일 사용으로 통일했다.
- gf가 발견한 별칭·이슈 URL 누락은 최신 기록에 반영했다.
- glm-z가 제안한 기존 Serve/Funnel 설정 보호·DNS 준비·중지 및 원복·인증 구성 누락 검증은 AC-23~25에 반영했다. 기존 설정의 소유·범위 확인을 공개 전 조건으로 둔다.
- `.gitignore` 부재는 확인했으며 실제 시크릿 파일 생성·커밋 전에 반영할 작업으로 남겼다. 이번 산출물은 비밀 없는 Markdown 문서다.
